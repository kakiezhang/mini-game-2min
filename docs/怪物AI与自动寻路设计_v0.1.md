# 《120 秒下班》怪物 AI 与自动寻路设计 v0.1

> 文档状态：待实现、待实机调优  
> 编写日期：2026-09-16  
> 适用范围：Bug 怪、需求变更怪、会议怪、老板  
> 代码基线：`822eed7`

## 1. 目的

本文档定义普通怪物和老板的感知、巡逻、追击、局部避障、群体分离、接触攻击及卡住恢复规则，作为后续实现、调试和验收的统一依据。

本次设计重点解决以下问题：

- 怪物出生后无条件知道主角位置，缺少发现和丢失目标的过程。
- 主角与怪物隔墙时，怪物可能持续顶墙或停在原地。
- 怪物没有待机与巡逻行为，未发现主角时仍然全图追击。
- 多只怪物会争抢同一个目标点，模型容易重叠或堆成一团。
- 当前分离只有方向修正，没有可靠的重叠解除。
- 不同碰撞半径的怪物共用同一套导航间距。
- 缺少卡住检测、自动恢复和可视化调试手段。

## 2. 设计目标

### 2.1 玩家体验目标

- 怪物只有在合理条件下发现主角，墙体能够遮挡视觉。
- 怪物丢失主角后会前往最后已知位置搜索，而不是立刻放弃或隔墙锁定。
- 未警觉的怪物能够在合理区域内巡逻、停留和转向。
- 怪物能够绕过办公室墙体、家具和关闭的电梯门。
- 多只怪物接近主角时保持可辨识的间距，不大面积穿模。
- 不同怪物具有可以从移动方式中感知到的行为差异。
- 老板出现后持续制造撤离压力，不受普通警戒范围限制。

### 2.2 工程目标

- 关键距离、时间、权重和更新频率集中配置，不散落在业务代码中。
- 全局寻路、局部避障、感知和动画状态职责清晰。
- 在当前最多 18 只敌人的规模下保持实现简单、稳定且易于调试。
- 能够显示怪物状态、目标、路径、流场和卡住信息。
- 为墙后追击、动态障碍、怪物分离和脱困建立自动测试。

### 2.3 v0.1 暂不处理

- 不引入完整行为树框架。
- 不引入 NavMesh、RVO 或 ORCA 等复杂人群系统。
- 不做潜行游戏级别的光照、噪声传播和逐骨骼视线判定。
- 不让怪物之间互相造成伤害。
- 不实现长期学习、阵营关系或跨局记忆。

## 3. 当前实现基线

当前实现位于 `src/navigation.ts` 与 `src/main.ts`，主要行为如下：

- 所有敌人生成后立即以主角为目标。
- 静态障碍被离散为 40 世界单位大小的二维网格。
- `NavigationWorld` 维护一份以目标格为终点的流场距离数据。
- 目标距离较近且直线路径可通行时，怪物直接向目标移动。
- 距离主角 210 以内时，每只普通怪物使用随机角度和随机半径选择环绕目标。
- 普通怪物每 80ms 计算一次两两分离方向。
- 障碍碰撞通过圆形碰撞体沿 X、Z 轴分别滑动处理。
- 生成点会检查占用状态及是否能到达主角。

已有实现提供了可复用的网格、障碍碰撞和流场基础，但还不是完整的敌人 AI。尤其需要注意：

- `NavigationWorld` 当前只缓存一个流场目标；多个不同环绕目标会切换缓存。
- 流场使用固定 `navigationClearance = 36`，不能准确表达所有怪物体型。
- 分离向量最终会与寻路方向一起归一化，分离强度没有被完整保留。
- 两只怪物完全重合时，当前分离逻辑不会产生推开方向。
- 没有记录怪物状态、最后已知位置、路径进度或卡住时间。

## 4. 总体架构

怪物移动分成四个层次：

1. **行为决策层**：决定巡逻、调查、追击、搜索或攻击。
2. **全局寻路层**：决定如何绕过房间、墙体和大型家具到达目标区域。
3. **局部移动层**：处理路径跟随、墙边修正、槽位接近和怪物间软分离。
4. **碰撞修正层**：阻止穿过静态障碍，并解除怪物之间已经发生的重叠。

每层只输出下一层需要的数据：

```text
行为状态 -> 行为目标点
行为目标点 -> 全局路径或流场方向
路径方向 + 分离 + 槽位 -> 期望速度
期望速度 -> 障碍移动与重叠修正 -> 最终位置
```

## 5. 怪物状态机

### 5.1 状态定义

| 状态 | 含义 | 主要行为 |
|---|---|---|
| `spawning` | 刚刚生成 | 确认落点有效，短暂禁止接触伤害 |
| `patrolIdle` | 巡逻点停留 | 原地观察，等待下一巡逻目标 |
| `patrolMove` | 前往巡逻点 | 沿缓存路径移动 |
| `investigate` | 发现可疑目标 | 转向声音或报警位置，确认主角 |
| `chase` | 已确认主角 | 使用共享追击流场接近主角 |
| `attack` | 已进入攻击范围 | 占据接近槽位，执行接触攻击 |
| `search` | 暂时丢失主角 | 前往最后已知位置并短暂搜索 |
| `stuckRecovery` | 检测到卡住 | 重新居中、换路径点或重新寻路 |
| `dead` | 已死亡 | 停止感知、寻路、碰撞和攻击 |

### 5.2 状态流转

```text
spawning
   └─> patrolIdle <──> patrolMove
          │                │
          └──── 感知事件 ──┴─> investigate
                                  │
                                  ├─ 确认主角 -> chase <──> attack
                                  │                │
                                  └─ 超时 ───────> patrolMove
                                                   │
                           丢失视线并超过记忆时间 ─┘
                                                   v
                                                 search
                                                   │
                                  重新发现主角 ────┤
                                  搜索超时 ───────> patrolMove

任何移动状态 ── 卡住 ──> stuckRecovery ── 恢复原状态
任何存活状态 ── HP 为 0 ──> dead
```

### 5.3 状态迟滞

发现和丢失目标不能使用同一个距离阈值，否则怪物会在边界处频繁切换状态。

- 进入追击使用较小的发现距离。
- 离开追击使用较大的丢失距离，并要求连续一段时间没有视觉。
- 短暂被墙体遮挡时继续前往最后已知位置。
- `attack` 与 `chase` 之间保留约 10 世界单位的距离迟滞。

## 6. 感知系统

### 6.1 距离计算

主角到怪物与怪物到主角是同一个距离，计算量没有区别。每个怪物使用距离平方进行初筛：

```ts
const dx = playerX - enemyX;
const dz = playerZ - enemyZ;
const distanceSquared = dx * dx + dz * dz;
```

当前最多只有 18 只敌人，逐个检查为 `O(N)`，无需为感知额外建立空间索引。只有当敌人规模提升到约 50～100 只后，才考虑以主角为中心查询空间网格。

### 6.2 感知来源

| 来源 | 规则 | 结果 |
|---|---|---|
| 近距离感知 | 主角进入近身范围，不检查墙体 | 立即进入 `investigate` 或 `chase` |
| 视觉 | 距离、视野角度和墙体射线同时通过 | 确认主角并进入 `chase` |
| 枪声 | 主角开火且怪物位于听觉范围 | 前往开火位置调查 |
| 受击 | 怪物被主角命中 | 无条件确认主角并追击 |
| 同伴报警 | 已警觉怪物通知附近同类 | 接收方前往报警位置调查 |

近距离感知用于避免主角贴到怪物背后仍完全无反应。视觉和枪声负责中远距离发现。

### 6.3 视觉遮挡

视觉检测按以下顺序执行：

1. 距离平方是否小于视觉范围平方。
2. 主角是否处于怪物视野夹角内。
3. 从怪物到主角的二维射线是否先撞到活动障碍。

墙体、硬家具和关闭的电梯门会遮挡视觉。其他怪物不遮挡视觉，避免人群频繁造成感知闪烁。

`patrolIdle` 时怪物会缓慢改变观察方向；移动时视野朝向取当前移动方向。

### 6.4 目标记忆

怪物确认主角后记录：

- `lastSeenPlayerX`
- `lastSeenPlayerZ`
- `lastSeenAt`
- `lastHeardX`
- `lastHeardZ`
- `lastHeardAt`

追击中看不到主角时，怪物仍前往最后看见的位置。连续超过目标记忆时间且没有新的声音或报警，才进入 `search`。

### 6.5 更新频率

- 近距离检测：每帧随接触检测执行。
- 视觉、听觉和同伴报警：每只怪物约 8Hz。
- 使用怪物 ID 将检测时刻错开，避免同一帧集中计算。
- 距离主角很远且不在追击状态的怪物可降为 4Hz。

## 7. 巡逻系统

### 7.1 巡逻区域

地图按语义划分巡逻区域：

- 工位区
- 会议室
- 老板办公室
- 茶水间
- 电梯与公共走廊

普通怪物生成后记录 `homeZone`。默认优先在出生区域巡逻，偶尔允许移动到相邻区域，不允许每次随机横跨整张地图。

### 7.2 巡逻目标选择

巡逻目标必须：

- 位于可通行导航格中心或预先定义的巡逻点。
- 与当前怪物碰撞半径兼容。
- 与当前位置存在有效路径。
- 不在墙体、家具、门洞中心或其他禁停区域内。
- 与当前位置保持最小距离，且不连续选择相同目标。

选择顺序：

1. 当前区域内未访问的候选点。
2. 当前区域内任意有效点。
3. 相邻区域的有效入口点。
4. 无有效点时原地等待，稍后重试。

### 7.3 巡逻节奏

- 到达巡逻点后等待 0.6～1.8 秒。
- 等待期间缓慢转向一次，形成观察动作。
- 每只怪物使用稳定的随机种子，避免刷新后所有怪同步停走。
- 巡逻速度为自身追击速度的 45%～65%。
- 怪物巡逻时不显示血条，除非已经受伤。

### 7.4 巡逻路径

巡逻目标彼此不同，不使用全局共享的单目标流场。选择新巡逻点时低频执行一次 A*，并缓存路径点；到达路径点后才推进到下一个。

如果当前路径因为电梯门等动态障碍失效，则丢弃路径并重新计算。

## 8. 全局寻路

### 8.1 追击流场

所有正在追击主角的怪物共享以主角所在导航格为终点的流场。流场只在以下条件下重建：

- 主角进入新的导航格。
- 活动障碍版本发生变化，例如电梯门打开。
- 导航体型类别发生变化且对应缓存不存在。

不能为每只怪物的环绕点单独重建全局流场。远距离阶段先共享到达主角附近的方向，进入局部接近范围后再切换到槽位移动。

### 8.2 导航体型类别

不同体型使用不同的障碍膨胀间距。v0.1 使用三档缓存，避免为每个精确半径维护一套流场：

| 类别 | 建议通行半径 | 当前适用对象 |
|---|---:|---|
| `small` | 18 | 需求变更怪 |
| `medium` | 30 | 主角、会议怪、老板 |
| `large` | 36 | Bug 怪 |

最终归类以运行时碰撞半径为准。通道如果只允许小体型通过，大体型流场必须将其视为不可通行。

### 8.3 直线捷径

当怪物与目标之间不存在静态障碍时，可以跳过中间网格点直接移动。直线检测必须使用怪物自身半径，不能只检查中心射线。

### 8.4 动态障碍

电梯门等动态障碍状态改变后：

- 增加障碍版本号。
- 使相关流场和巡逻路径失效。
- 在下一次寻路更新时按需重建，不在同一帧为所有路径同步重建。

## 9. 主角周围接近槽位

### 9.1 目的

所有怪物都把主角中心当作终点，会导致拥挤和穿模。进入主角附近后，需要为怪物分配主角周围的接近槽位。

### 9.2 槽位生成

- 第一圈半径由主角半径、怪物半径和攻击间距共同决定。
- 槽位之间的弧长必须容纳对应怪物直径及少量间隔。
- 第一圈没有可用槽位时使用第二圈。
- 落在墙体或家具中的槽位标记为不可用。
- 同一槽位同一时间只分配给一只怪物。
- 槽位分配保持一段时间，不因每帧距离微小变化而交换。

### 9.3 分配优先级

1. 老板拥有最高优先级，普通怪物需要让开。
2. 已进入攻击状态的怪物优先保留当前槽位。
3. 选择与怪物当前角度最接近的有效槽位，减少交叉换位。
4. 需求变更怪可以偏向侧翼槽位。
5. 会议怪占用更宽的槽位间隔。

槽位只负责接近目标，不替代怪物之间的局部避让和硬碰撞。

## 10. 怪物间分离与碰撞

### 10.1 软分离

怪物还没有发生重叠时，根据邻居距离施加逐渐增强的分离速度。

```text
期望间距 = radiusA + radiusB + personalGap
```

`personalGap` 首版建议为 8～14，不再对所有怪物固定额外增加 30。

软分离只改变期望速度，不能把路径方向完全覆盖。建议保留各分量权重后再限制最终速度，而不是先相加再无条件归一化为满速。

### 10.2 硬重叠修正

完成静态障碍移动后，检查怪物对是否真实重叠：

```text
overlap = radiusA + radiusB + hardGap - distance
```

当 `overlap > 0` 时：

- 普通怪物双方各承担一半修正距离。
- 老板视为高质量实体，普通怪物承担主要修正距离。
- 修正后的位置必须重新通过静态障碍占用检查。
- 每帧最多进行 2 次小幅迭代，避免过度抖动。
- 两个中心完全重合时，根据双方 ID 生成稳定且相反的推开方向。

### 10.3 性能

当前最大 18 只敌人，两两检查最多 153 对，10～12.5Hz 的软分离和每帧小规模硬修正可以接受。敌人数显著增加后，再将邻居查询替换为空间哈希。

## 11. 卡住检测与恢复

### 11.1 卡住判定

怪物处于移动状态且同时满足以下条件时累计卡住时间：

- 当前期望速度大于最小阈值。
- 最近采样窗口中的实际位移小于阈值。
- 到行为目标的距离没有明显减少。

需要记录：

- 上次采样位置和时间。
- 到当前目标的最近距离。
- 连续卡住时长。
- 最近一次恢复等级和恢复时间。

### 11.2 分级恢复

| 卡住时长 | 恢复动作 |
|---:|---|
| 0.5 秒 | 尝试回到当前导航格中心 |
| 1.0 秒 | 跳过疑似无效路径点并重新寻路 |
| 1.8 秒 | 临时选择相邻可通行格作为绕行点 |
| 3.0 秒 | 放弃当前槽位或巡逻点，重新选择行为目标 |
| 5.0 秒 | 仅当怪物不在玩家视野内时，重新放置到邻近安全点 |

恢复成功后回到进入 `stuckRecovery` 前的状态。玩家可见范围内禁止直接瞬移。

### 11.3 故障分类

调试信息应区分：

- `no-flow-direction`：流场没有有效下降方向。
- `blocked-waypoint`：当前路径点被动态障碍阻挡。
- `static-collision`：期望移动被墙体或家具完全阻止。
- `crowd-blocked`：被其他怪物持续阻挡。
- `invalid-slot`：接近槽位不可通行。
- `visual-only`：位置发生变化但动画未进入移动状态。

## 12. 接触攻击

- 只有主角与怪物碰撞圆接触时才能造成接触伤害。
- 静态墙体必须阻止双方圆形碰撞体重叠，因此不能隔墙攻击。
- 进入 `spawning` 后提供约 0.35 秒攻击延迟，避免加载或出生瞬间掉血。
- 接触冷却沿用各怪物现有配置。
- 会议怪的减速效果仍然只在实际接触伤害成功时触发。
- 处于第二圈槽位的怪物不得隔着第一圈怪物攻击主角。

`attack` 状态不要求怪物原地不动；它仍可低速调整槽位，防止主角移动后怪物僵住。

## 13. 怪物行为差异

| 怪物 | 巡逻特点 | 发现与追击 | 人群特点 |
|---|---|---|---|
| Bug 怪 | 短暂停留，频繁换点 | 听觉较强，发现后直接接近 | 倾向小群报警和第一圈围攻 |
| 需求变更怪 | 巡逻速度较快 | 视觉较远，优先选择侧翼槽位 | 保持较小间距，快速换位 |
| 会议怪 | 会议室停留时间更长 | 感知略弱，追击较慢 | 体型较宽，占用更大槽位 |
| 老板 | 不巡逻 | 出现后始终知道主角大致位置 | 高质量实体，普通怪物主动让路 |

老板仍然需要使用全局寻路绕墙，不能因为持续追击而忽略障碍。若短暂失去直视，老板继续使用主角当前所在格的共享流场，不进入普通怪物的搜索状态。

## 14. 初始配置建议

以下数值是首版实现初值，必须通过实机测试调整：

### 14.1 全局 AI 参数

| 参数 | 初值 | 说明 |
|---|---:|---|
| `perceptionInterval` | 0.125 秒 | 普通感知约 8Hz |
| `farPerceptionInterval` | 0.25 秒 | 远处未警觉怪物约 4Hz |
| `investigateDuration` | 0.3 秒 | 确认主角前的短暂反应 |
| `targetMemoryDuration` | 2.5 秒 | 丢失视线后的目标记忆 |
| `searchDuration` | 3.0 秒 | 最后已知位置的搜索时间 |
| `allyAlertRadius` | 220 | 同伴报警范围 |
| `personalGap` | 10 | 软分离附加距离 |
| `hardGap` | 2 | 硬碰撞附加距离 |
| `separationInterval` | 0.08 秒 | 软分离更新频率 |
| `stuckSampleInterval` | 0.5 秒 | 卡住位移采样窗口 |
| `stuckMinDisplacement` | 5 | 采样期最小有效位移 |
| `spawnAttackDelay` | 0.35 秒 | 出生后的接触伤害延迟 |

### 14.2 分怪物感知参数

| 怪物 | 近身发现 | 视觉距离 | 水平视野角 | 听觉距离 | 丢失距离 | 巡逻速度倍率 |
|---|---:|---:|---:|---:|---:|---:|
| Bug 怪 | 170 | 480 | 220° | 680 | 620 | 0.60 |
| 需求变更怪 | 180 | 520 | 200° | 700 | 660 | 0.65 |
| 会议怪 | 160 | 420 | 220° | 600 | 560 | 0.48 |
| 老板 | 全局 | 全局 | 360° | 全局 | 不丢失 | 不巡逻 |

近身发现如果需要忽略墙体，范围不得大于最薄墙体两侧可同时达到的距离；实测发现隔墙误触发时，应改为“近身距离 + 简化遮挡检查”。

## 15. 建议的数据结构

怪物运行时需要新增独立 AI 数据，避免所有字段继续堆积在渲染实体上：

```ts
type EnemyAiState =
  | "spawning"
  | "patrolIdle"
  | "patrolMove"
  | "investigate"
  | "chase"
  | "attack"
  | "search"
  | "stuckRecovery"
  | "dead";

type EnemyAiRuntime = {
  state: EnemyAiState;

  targetX: number;
  targetZ: number;
  lastSeenPlayerX: number;
  lastSeenPlayerZ: number;
  lastSeenAt: number;
  lastHeardX: number;
  lastHeardZ: number;
  lastHeardAt: number;
  path: NavigationPoint[];
  pathIndex: number;
  approachSlotId?: number;
  nextPerceptionAt: number;
  stuckSince?: number;
  lastProgressAt: number;

```

建议将逻辑逐步拆分为：

```text
src/ai/enemy-ai.ts            状态机和行为决策
src/ai/perception.ts          视觉、听觉和报警
src/ai/patrol.ts              区域与巡逻目标
src/ai/approach-slots.ts      主角周围槽位
src/ai/crowd.ts               软分离和硬重叠修正
src/navigation.ts             网格、路径、流场和静态碰撞
```

不要求一次性完成文件拆分；应先保证行为正确，再按职责整理。

## 16. 调试工具

开发模式增加可切换的 AI 调试层，默认关闭：

- 怪物头顶显示 `id / kind / state`。
- 绘制近身、视觉、听觉和丢失范围。
- 绘制当前行为目标、最后已知位置和缓存路径。
- 绘制当前导航格、流场方向和不可通行格。
- 绘制主角周围接近槽位及其占用者。
- 用不同颜色显示寻路、分离、槽位和最终速度向量。
- 显示卡住计时、恢复等级和故障分类。
- 支持固定随机种子和生成指定怪物。
- 支持将时间跳转到 15、40、90 秒进行快速验证。

没有调试层时，很难区分“没有路径”“被墙阻挡”“被同类挤住”和“只有动画没有播放”。调试层应在正式调参前完成。

## 17. 性能预算

以当前 `GAME.maxEnemies = 18` 为基准：

- 位置移动、静态碰撞和动画：每帧。
- 近距离接触：每帧。
- 软分离：10～12.5Hz。
- 视觉、听觉和报警：每只怪物约 8Hz，错峰执行。
- 巡逻 A*：只在选择新目标或路径失效时执行。
- 追击流场：只在主角跨格、动态障碍变化或体型缓存缺失时重建。
- 硬重叠修正：每帧最多两轮，当前规模可直接两两检查。

性能优化顺序应为：先降低更新频率和避免重复重建，再考虑空间哈希、对象池或更复杂的数据结构。

## 18. 实现阶段

### 阶段 A：可观测性与数据结构

- 增加 AI 状态和运行时字段。
- 增加固定随机种子和指定怪物生成方式。
- 增加状态、目标、路径和卡住信息的调试显示。
- 保持现有追击行为不变，确认重构没有引入回归。

### 阶段 B：修正全局寻路

- 将追击流场改为按目标格和体型类别缓存。
- 环绕点不再触发全局流场重建。
- 增加动态障碍失效机制。
- 增加不可达、墙角和不同半径通道测试。

### 阶段 C：感知、记忆与巡逻

- 实现近身、视觉、枪声、受击和同伴报警。
- 实现状态迟滞和最后已知位置。
- 建立巡逻区域、巡逻点和低频 A* 路径。
- 老板保持出现后全局追击。

### 阶段 D：人群移动

- 实现稳定接近槽位。
- 重写软分离，使强度和权重有效。
- 增加硬重叠修正和老板质量优先级。
- 验证狭窄门洞不会形成永久死锁。

### 阶段 E：脱困与调优

- 实现卡住检测、故障分类和分级恢复。
- 分别调试四种怪物的行为参数。
- 完整运行 120 秒，检查生成、追击、战斗和撤离。
- 记录最终参数并更新开发进度文档。

## 19. 验收场景

### 19.1 感知

- 主角在视觉范围外时，未警觉怪物继续巡逻。
- 主角进入视觉范围且无遮挡时，怪物转入追击。
- 主角和怪物隔墙时，怪物不能凭视觉直接确认主角。
- 主角开枪后，听觉范围内怪物前往枪声位置调查。
- 怪物被击中后立即追击主角。
- 追击怪物可以惊动附近同类，但不会无限链式惊动整张地图。

### 19.2 寻路

- 主角与怪物分处墙体两侧时，怪物会寻找门洞绕行。
- 电梯门打开后，相关流场和路径能够更新。
- 小体型可通过而大体型不可通过的通道结果符合配置。
- 怪物不会持续朝不可通行目标点顶墙。

### 19.3 巡逻与搜索

- 怪物在所属区域内移动、停留并选择新目标。
- 丢失主角后前往最后已知位置，而不是追踪实时隔墙坐标。
- 搜索超时后恢复巡逻。
- 多只怪物的巡逻节奏不会完全同步。

### 19.4 人群与碰撞

- 两只怪物不会长时间模型重叠。
- 两只怪物中心完全重合时可以稳定分开。
- 多只怪物接近主角时分布在不同槽位和圈层。
- 老板经过时普通怪物让路，老板不会被小怪永久堵住。
- 怪物在门口拥挤后仍能逐步通过或重新选择路线。

### 19.5 卡住恢复

- 故意将怪物生成在墙角附近，能够触发并显示卡住原因。
- 路径点失效后能够重新寻路。
- 恢复过程中不会穿墙。
- 玩家视野内不会发生明显瞬移。

### 19.6 回归

- Walk 只在实际移动时播放，停止时使用当前待机姿势。
- 接触伤害、会议怪减速、血条、击中闪白和掉落保持正常。
- 多只动画模型独立播放，不互相重置动画。
- 生产构建通过，完整 120 秒流程无明显帧率下降。

## 20. 完成标准

只有同时满足以下条件，怪物 AI 与寻路改造才算完成：

- 普通怪物具备巡逻、发现、追击、丢失、搜索和恢复流程。
- 墙体能够阻挡视觉，但不能让已发现怪物永久卡住。
- 多只怪物能够保持合理间距并围绕主角分配位置。
- 不同体型的怪物使用匹配的通行间距。
- 卡住问题能够被检测、分类并自动恢复。
- 四种怪物行为差异清晰，且仍符合原有战斗定位。
- 调试层能解释怪物当前为什么移动或为什么不移动。
- 自动测试、生产构建和一局 120 秒人工验收全部通过。

## 当前怪物 AI 的真实情况

目前的敌人移动是“基础寻路”，不是完整 AI：

- 所有怪物生成后立即知道主角的实时位置，没有发现范围。
- 没有待机、巡逻、警觉、丢失目标和搜索状态。
- 墙体不参与视觉遮挡，因为当前尚未实现视觉感知。
- 远处怪物尝试通过共享流场前往主角附近。
- 近处怪物通过随机环绕目标减少直接堆叠。
- 怪物之间只有软分离，没有可靠的硬重叠修正。
- 没有路径进度、卡住检测、故障分类或自动脱困。
- 单份流场缓存和固定导航间距不能充分支持不同目标与不同体型。

完整设计见 [怪物 AI 与自动寻路设计 v0.1](怪物AI与自动寻路设计_v0.1.md)。

## 已知问题

- Bug 怪在距离较远、隔墙或处于特定出生位置时，可能看起来完全不移动。
- 怪物可能持续朝墙体或无效局部目标移动，缺少可观测的失败原因。
- 多只怪物接近时可能发生重叠、挤成一团或堵住门口。
- 近距离随机环绕目标可能落在障碍内，并可能引起流场目标频繁切换。
- 不同碰撞半径的怪物仍然共用固定的导航间距。
- 当前只有 Walk 动画；Idle 使用 Walk 中间姿势冻结，尚无独立攻击、受击和死亡动画。
- 需求变更怪和老板还没有真实骨骼模型。
- JavaScript 生产 chunk 超过 500 kB，暂未做代码拆分。
- 自动测试和完整 120 秒回归测试尚不充分。

## 当前最高优先级：怪物 AI 与自动寻路

设计文档已经完成，接下来按以下阶段实现：

1. **可观测性与数据结构**：增加 AI 状态、目标、路径、卡住信息及调试显示。
2. **修正全局寻路**：按目标格和体型缓存流场，避免局部目标反复重建全局流场。
3. **感知、记忆与巡逻**：实现视觉、听觉、受击报警、最后已知位置和区域巡逻。
4. **人群移动**：实现接近槽位、有效软分离、硬重叠修正和老板让路优先级。
5. **脱困与调优**：实现卡住检测、分级恢复、自动测试和完整 120 秒验收。

当前最合适的下一项实现任务是阶段 A。应先获得调试可观测性，再修改寻路算法，以便准确解释怪物为什么移动或为什么不移动。

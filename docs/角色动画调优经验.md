# 角色动画调优经验

用于记录本项目已经排查、修复并验证过的动画问题。案例中的参数只适用于对应资产；遇到相似外观时，先验证原因，再选择修复方法。

## 案例：Shoot 左手腕扭转塌缩

记录日期：2026-09-23。资产：`ksman_v3_shoot.fbx`，基础蒙皮：`ksman_v3_walk.fbx`；运行时模型：`ksman_v3_walk_1k_meshopt.glb`。

关键词：手腕变细、莲藕人、拧糖纸、扭转塌缩、candy-wrapper、前臂、Mixamo、线性蒙皮。

### 现象与结论

Shoot 的整体站姿与手掌方向基本正确，但左手和小臂连接处被拧成尖细的连接点，看起来像旋转了一整圈。放大、多角度观察比完整人物截图更容易暴露问题；此前的全身预览未充分发现这一处缺陷。

本次原因是：**手部与前臂的变形旋转差过大，线性蒙皮在两者交界处收缩。** 骨骼缩放接近 1，合并后的骨骼姿态也基本复现原始 Shoot，因此不能把这个现象归因于合并时凭空多转了一圈。

这不证明 Mixamo 内部采用了某种特定分配算法，也不证明所有类似症状都由相同原因造成。原始 Shoot 是 Without Skin 文件，只有骨架，无法直接据此判断它在其他人物网格上的表现。

### 140° 到底指什么

这里测的是**相对于当前蒙皮绑定姿势，手部与前臂的变形旋转之间的扭转分量**，不是人体腕关节角度，也不是动画累计转了多少圈。

在同一坐标系中，使用当前骨骼姿态矩阵 `P` 和绑定姿势矩阵 `B` 得到变形矩阵 `D = P × inverse(B)`；比较前臂与手部的变形旋转，并沿绑定姿势中的前臂轴提取扭转分量。

Mixamo 附加动作与基础蒙皮文件的绑定轴向可能不同。此次左前臂绑定旋转相差约 58°、左手约 64°。骨骼同名、层级相同，并不意味着可以直接复制局部旋转曲线；诊断也不能只看某个 Euler 通道的数值。

人的翻掌由前臂等部位共同完成。这套骨架没有专门分摊前臂扭转的辅助骨骼；当差异集中在腕部，受前臂与手骨共同影响的顶点在矩阵混合后向内收缩，就出现了“拧糖纸”的外观。

### 本次排查证据

| 检查项 | 结果与含义 |
| --- | --- |
| FBX 内容 | 1 个骨架、0 个网格；65 根骨骼及父子关系与基础模型一致 |
| 动作长度 | 30 FPS，第 1–41 帧，导出为第 0–40 帧，约 1.33 秒 |
| 修正前姿态复现 | 合并后最大骨骼位置误差约 0.081 mm；支持排除本次合并产生明显姿态偏移 |
| 左手腕扭转分量 | 各源采样帧约 −143.57° 至 −138.39°，并非偶发一帧翻转 |
| 手骨缩放 | 接近 `(1, 1, 1)`，不是直接缩小了手腕骨骼 |
| 近景对比 | 原腕部明显挤成尖点；分摊扭转后连接处明显改善 |

毫米换算依据本次模型的原生米制尺寸；不要直接套用到已经缩放为游戏高度的实例上。

### 可复用的排查顺序

1. 保留调优前的 GLB，记录出问题的动作、左右侧和时间点。暂停后拖动时间轴，并检查动作中段、首尾与两个动作切换时的表现。
2. 检查原始 FBX 的骨架、网格、骨骼名称、父子关系和帧率。Without Skin 动作应与已有蒙皮骨架合并，不能把它当作独立人物网格。
3. 对照源动作、未压缩合并结果和最终压缩模型。若骨骼姿态已有明显差异，优先修合并／重定向；若只在压缩后异常，检查动画重采样和旋转精度。
4. 检查关节缩放、变形旋转差及受影响区域的权重。区分持续的大角度扭转、个别帧的不连续，以及错误骨骼牵引。不要仅凭“像转了 360°”就修改旋转角度。
5. 同时看前后、侧面和局部近景。验证修复是否把塌缩转移到了肘部、袖口，或者改变了手掌与手指的握持方向。

### 本次修复方法

使用已有 [动画合并脚本](../scripts/merge_character_animations.py) 的 `share_forearm_twist()`，在 Shoot 的每个源采样帧上：

1. 以当前蒙皮的绑定姿势为依据计算左手相对前臂的扭转。
2. 将其中 50% 分摊为左前臂绕“肘到腕”轴的旋转。
3. 保留手部及其子骨骼的目标姿态矩阵，按**同一帧的新父骨骼矩阵**重新计算局部变换，使手掌方向和手指姿势得到补偿。
4. 对扭转角做跨帧连续化，避免跨过 ±180° 表示边界时发生跳变。

对应导出参数：

```text
--clip Shoot=ksman_v3_shoot.fbx --clip-forearm-twist Shoot=Left:0.5
```

完整生成命令见 [README 的角色动作预览与生成说明](../README.md)。这次只修改 Shoot 中的扭转分配，不修改网格、权重、骨骼数量或 Idle／Walk。重新生成本版资产时需要保留该参数，否则会重新出现原来的腕部问题。

**`0.5` 是本次资产的调优值，不是所有手腕问题的默认修复。** 参数支持指定动作与左右侧；不要无依据地同时修改另一只手或全部动作。若分摊导致肘部／袖口明显变形，或多个动作都暴露严重问题，应进一步评估权重、辅助扭转骨骼、绑定姿势或动作选择，而不是不断加大分摊比例。

### 验证结果与复查方法

压缩后的运行时 GLB 在 81 个采样点（含半帧插值）上的检查结果：

| 验证项 | 本次结果 |
| --- | --- |
| 左手与前臂的相对变形旋转角 | 最大约 79.33°；这是完整相对旋转角，与前面的有符号轴向扭转分量不是同一指标 |
| 所有关节位置对比修正前 | 最大差异约 0.043 mm |
| 除左前臂外的骨骼姿态矩阵 | 最大元素误差约 `0.000099`；包括手掌及手指 |
| Idle 与 Walk | 动画数据对比一致；Idle 循环仍通过检查 |
| 资源结构 | 65 根骨骼、49,478 三角面；1K WebP／Meshopt；压缩模型约 939.53 KB |
| 播放与构建 | 浏览器 Shoot 放大预览与连续播放、动画回归测试、生产构建通过 |
| 游戏尺寸配置 | 保持视觉高度 118、碰撞半径 30；模型原生尺寸与这些游戏单位分开处理 |

当前 [动画回归脚本](../scripts/validate_character_transitions.mjs) 会检查本版 Shoot 的腕部相对变形角小于 90°。这是该案例的回归阈值，**不是通用人体限制，也不能替代外观验收**。

日常验证：

```bash
npm run test:animation
node scripts/validate_character_loop.mjs ksman_v3_walk_1k_meshopt.glb
npm run build
git diff --check
```

对新一轮修复，开始前先在独立临时目录保存当前模型，保留这一路径；完成后在运行过 `npm run test:animation` 的基础上，将调优前 GLB 的路径作为参数传给：

```text
node scripts/validate_character_transitions.mjs <调优前GLB路径>
```

只有传入旧模型时，脚本才会核对所有关节位置、其他骨骼姿态以及 Idle／Walk 是否保持一致。未传旧模型时，输出的零对比误差不代表完成了前后对照，应看 `baselineChecked` 是否为 `true`。

最后刷新 `character-preview.html`，选择 Shoot，在 0.25× 速度及暂停状态下检查腕部、手掌、肘部和袖口。若通过拖入文件加载了旧版本，应重新选择修正后的文件。用户已反馈手腕“确实好一些了”；本次记录的是已改善且通过上述检查的结果，不代表所有持枪细节已经最终验收。

### 避免的误修

- 不把“大角度扭转”直接解释成模型差、必须重新生成 Hunyuan 模型。
- 不把手腕直接放大或给整段手臂加粗来掩盖塌缩。
- 不随意清零骨骼位移、强制缩放为 1，或删除旋转轨道；这些操作可能破坏已正确的姿势。
- 不单独旋转前臂却忘记补偿手部子骨骼，否则握持方向会改变。
- 不以手腕局部改善代替整条手臂、多动作和浏览器最终压缩资产的验收。

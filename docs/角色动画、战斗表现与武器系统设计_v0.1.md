# 《120 秒下班》角色动画、战斗表现与武器系统设计 v0.1

> 文档状态：待评审  
> 编写日期：2026-09-20  
> 适用范围：主角、Bug 怪、需求变更怪、PPT／会议怪及后续老板  
> 关联文档：[怪物 AI 与自动寻路设计 v0.1](怪物AI与自动寻路设计_v0.1.md)、[MVP 技术实现方案 v0.1](120秒下班_MVP技术实现方案_v0.1.md)

> 实施进度：本稿的“当前”和“尚未”描述以 2026-09-20 为基线。主角 v3 的 Idle／Walk／Shoot 资产、切换控制与独立验收台已在 2026-09-23 完成；正式游戏开火联动和其余角色动作仍待实现。最新状态见 [开发进度](开发进度.md)。

## 1. 背景

当前主角、Bug 怪、需求变更怪和 PPT／会议怪已经使用真实骨骼模型，但每个模型只有一段 `Walk` 动画。运行时虽然定义了 `idle`、`walk`、`attack`、`hit` 和 `death`，角色目录实际只映射 `walk`；Idle 通过冻结 Walk 中间帧模拟，玩家和怪物每帧又都只根据移动方向切换 Walk／Idle。

因此，已有玩法状态没有得到相应的视觉表达：

- 主角射击和换弹时身体没有对应动作。
- 怪物进入攻击状态后仍然保持 Walk，伤害与动作没有关系。
- 怪物调查枪声或最后已知位置时没有环顾、嗅闻或扫描动作。
- 受击只有短暂闪白和缩放，缺少身体反应。
- 怪物死亡后立即播放粒子并从场景移除，没有死亡过程。
- 当前只有固定冲锋枪，攻击动作、判定和 HUD 都没有装备维度。

这些问题会同时削弱战斗反馈、角色辨识度和后续武器扩展。继续制作老板模型会把同一缺陷带到新角色上，因此应先建立完整的动画与战斗表现基础，再让老板直接按新标准制作。

## 2. 设计目标

### 2.1 玩家体验目标

- 玩家不看文字也能区分角色正在待机、移动、攻击、受击、搜寻还是死亡。
- 不同怪物通过独特攻击动作和效果形成明确身份：Bug 啃食、需求怪打拳、PPT 怪使用激光笔。
- 伤害发生的时间与动作命中瞬间一致，避免“还没打到就扣血”。
- 主角能够使用枪械、刀和空手攻击，并能从地面拾取或替换武器。
- 受击和击杀有清晰但不过度血腥的反馈，保持办公室喜剧风格。
- 竖屏手机上依然能够看清预警、攻击方向和命中结果。

### 2.2 工程目标

- 玩法状态、动画状态和特效状态分层，避免把动画判断继续堆入 `main.ts`。
- 一次性动画具备优先级、播放锁、完成回调和事件时间点。
- 攻击判定由统一攻击定义驱动，支持射线、近战范围和预警光束。
- 每个角色使用同一骨骼上的多段动画，不为每个动作重复模型和贴图。
- 当前最多 13 只敌人的条件下，动画扩展不增加 draw call 数量，不引入游戏中途资源加载。
- 关键状态优先级、攻击命中时机、死亡清理和装备切换具备自动化测试。

### 2.3 v0.1 暂不处理

- 不做复杂背包、武器词条、耐久度或双持系统。
- 不一次加入大量枪械，只验证冲锋枪、刀和空手三种攻击形态。
- 不实现断肢、布娃娃或写实血液系统。
- 不在第一阶段实现逐骨骼上／下半身动画遮罩；先使用全身动作验证流程。
- 不重新引入与 `investigate` 重复的独立 AI `search` 状态。
- 老板模型与老板专属动作在本设计的基础阶段完成后再制作。

## 3. 设计原则

### 3.1 玩法状态是事实，动画负责表达

AI、武器和伤害系统决定角色真正做了什么；动画不能反过来成为不可查询的隐式玩法逻辑。攻击系统提交“开始攻击”和“命中事件”，动画控制器负责播放与反馈。

### 3.2 伤害必须与动作事件同步

- 玩家枪械保持输入即时响应：射击判定和 Shoot 动画同帧开始。
- 玩家近战、Bug 啃食和需求怪打拳在动画命中帧执行伤害。
- PPT 激光先预警，再在发射帧执行遮挡检测和伤害。
- 同一次攻击的命中事件只能触发一次，不能因低帧率跨过时间点而重复结算。

### 3.3 视觉状态与 AI 状态不是一一对应

AI 的 `patrolMove`、`investigate`、`chase` 都可能表现为 Walk；`investigate` 到达目标后才表现为 Search。动画层接收明确的表现意图，不直接复制整套 AI 状态机。

### 3.4 死亡立即停止玩法，延迟清理画面

HP 降到 0 时立即关闭攻击、碰撞、寻路和受击判定，但模型保留到 Death 动画与消散效果结束。这样不会发生“尸体继续攻击”，也不会像当前一样瞬间消失。

### 3.5 移动端可读性优先

攻击预警、命中特效和状态动作必须在实际游戏视角及角色尺寸下验收。离线放大后才能看见的手指或面部动作不能作为主要反馈。

## 4. 总体架构

角色表现按三层拆分：

```text
玩家输入 / 敌人 AI / 伤害结果
              ↓
      CharacterIntent
  locomotion + action + facing
              ↓
 CharacterAnimationController
  优先级、播放锁、混合、动画事件
              ↓
 AnimatedCharacter + CharacterEffects
  骨骼动画、闪白、粒子、消散、音效
```

建议新增或调整以下模块：

| 模块 | 职责 |
|---|---|
| `src/characters/character-animation-controller.ts` | 动画优先级、一次性动作、事件与回退状态 |
| `src/characters/animated-character.ts` | 加载多 Clip、执行淡入淡出、暴露动作完成事件 |
| `src/characters/catalog.ts` | 每个角色的 Clip 映射、播放速度和动作事件比例 |
| `src/combat.ts` | 统一射线、近战范围、光束遮挡和命中结果 |
| `src/equipment.ts` | 当前装备、拾取、替换和攻击定义选择 |
| `src/effects/character-combat-effects.ts` | 受击、死亡及怪物专属效果 |
| `src/ai/enemy-attack.ts` | 怪物攻击蓄力、命中、恢复和冷却 |

`main.ts` 只负责提交输入、实体位置和事件，不负责拼装具体角色的动画细节。

## 5. 动画状态设计

### 5.1 状态分类

```ts
type LocomotionState = "idle" | "walk";

type CharacterActionState =
  | "none"
  | "search"
  | "shoot"
  | "reload"
  | "melee"
  | "hit"
  | "death";
```

Locomotion 持续记录角色是否移动；Action 是可能覆盖 Locomotion 的短时表现。这样一次性动作结束后，可以准确回到当前的 Idle 或 Walk，而不是固定回 Idle。

### 5.2 优先级与打断规则

| 优先级 | 状态 | 规则 |
|---:|---|---|
| 5 | `death` | 不能被任何状态打断，结束后保持最后姿势并进入消散 |
| 4 | `hit` | 可打断攻击和搜索；同一短窗口内只重播或延长一次 |
| 3 | `shoot` / `reload` / `melee` | 按动作配置决定是否可被新攻击重启；可被 Hit 和 Death 打断 |
| 2 | `search` | 只在调查点附近播放，可被发现主角、Hit 和 Death 打断 |
| 1 | `walk` | 没有更高优先级动作且正在移动时循环 |
| 0 | `idle` | 默认循环状态 |

第一版采用全身动作。角色在 Shoot 或 Melee 动画期间仍可按玩法规则移动，但可能出现轻微滑步；实机明显时，再增加上半身骨骼遮罩或专门的移动攻击动画。

### 5.3 混合规则

- Idle 与 Walk 淡入淡出：`0.12s`。
- Attack 与 Reload：`0.06～0.1s`，保证操作响应。
- Hit：快速切入，`0.04～0.06s`。
- Death：快速切入但不回退。
- 角色转向继续使用现有平滑限速，不由动画 Root Motion 驱动。
- 所有移动和攻击 Clip 默认原地播放，世界位移仍由导航与玩家移动系统控制。

### 5.4 动画事件

每个一次性动作可定义归一化事件点：

```ts
type AnimationEventDefinition = {
  name: "fire" | "hit" | "reloadCommit" | "deathFx";
  normalizedTime: number;
};
```

例如：

- Punch 在 `0.42` 触发 `hit`。
- Bite 在 `0.48` 触发 `hit`。
- Laser 在 `0.58` 触发 `fire`。
- Reload 在 `0.78` 触发 `reloadCommit`，子弹在该时间点进入弹匣。

控制器记录已触发事件，确保掉帧跨过事件点时补触发一次，而不是漏掉或重复触发。

## 6. 角色动画清单

### 6.1 第一批必需 Clip

| 角色 | 必需 Clip | 表现目标 |
|---|---|---|
| 主角 | `Idle`、`Walk`、`Shoot`、`Reload`、`Hit`、`Death` | 枪械战斗闭环完整 |
| Bug 怪 | `Idle`、`Walk`、`Bite`、`Hit`、`Death` | 贴身后明显啃食，而不是继续走路 |
| 需求变更怪 | `Idle`、`Walk`、`Punch`、`Hit`、`Death` | 近战打击节奏清楚 |
| PPT／会议怪 | `Idle`、`Walk`、`Laser`、`Hit`、`Death` | 举起激光笔、预警并发射 |

### 6.2 第二批可选 Clip

| 角色 | 可选 Clip | 用途 |
|---|---|---|
| 主角 | `Punch`、`Slash`、`Pickup` | 空手、刀和拾取表现 |
| Bug 怪 | `Search` | 到达调查点后低头嗅闻或左右探查 |
| 需求变更怪 | `Search` | 到达调查点后左右张望 |
| PPT／会议怪 | `Search` | 使用激光笔缓慢扫描环境 |
| 全体 | `Spawn` | 取代当前纯淡入，强化出生身份 |

如果缺少专门 Search Clip，第一版可以使用 Idle 加程序化左右转向；不得因此重新使用 Walk 冻结姿势作为最终方案。

## 7. AI 状态与动画映射

| AI 状态 | 默认动画意图 | 说明 |
|---|---|---|
| `spawning` | Idle／Spawn | 出生完成前不可攻击或受击 |
| `patrolIdle` | Idle | 可叠加缓慢观察转向 |
| `patrolMove` | Walk | 使用巡逻速度播放倍率 |
| `investigate` 移动中 | Walk | 前往声音或最后已知位置 |
| `investigate` 到点 | Search | 原地观察，不新增独立 AI 状态 |
| `chase` | Walk | 使用追击速度播放倍率 |
| `attack` | 角色专属 Attack | 由攻击控制器决定蓄力、命中和恢复 |
| `stuckRecovery` | Walk | 继续表达主动脱困方向 |
| `dead` | Death | 立即退出 AI 更新和碰撞 |

### 7.1 搜寻表现

当前 AI 已经通过 `investigate` 支持视觉、近身发现、枪声、同伴报警和丢失目标调查。设计上保留该状态，增加一个到点观察阶段：

```text
前往调查点 → 进入观察半径 → Search 0.8～1.6 秒 → 返回巡逻
                          └→ 重新发现主角 → Chase
```

建议增加 `investigationObserveUntil` 或等价的表现计时字段。它只是 `investigate` 内部阶段，不进入全局 AI 状态枚举，从而避免恢复旧版 Search 与 Investigate 重复、状态抖动的问题。

## 8. 怪物攻击设计

### 8.1 Bug 怪：啃食

- 类型：近战单体。
- 进入攻击范围后停止主动前进，播放 Bite。
- Bite 命中帧重新确认距离；目标已离开则挥空。
- 命中时产生绿色故障碎屑、短促咬合反馈和现有伤害无敌帧。
- 攻击恢复结束后才能再次 Bite，冷却仍由配置控制。

### 8.2 需求变更怪：打拳

- 类型：近战小范围。
- Punch 命中帧使用前方扇形或圆形近战判定。
- 角色面向在出拳开始时锁定一小段时间，避免挥拳瞬间反向。
- 命中产生蓝色便签／需求卡片碎屑和轻微击退表现。
- 第一版击退只作用于视觉根节点，不修改主角碰撞位置，避免引入穿墙问题。

### 8.3 PPT／会议怪：激光笔

- 类型：中距离、有预警的光束攻击。
- 进入约 `220～420` 世界单位的偏好距离后停止接近；具体值在实机调优。
- 蓄力阶段显示从激光笔到主角附近的细预警线，持续约 `0.55～0.8s`。
- 发射帧重新检测墙体遮挡；墙体优先截断光束。
- 主角持续移动可以躲开锁定点；第一版在蓄力后半段停止跟踪，保留反应窗口。
- 命中造成伤害并延续会议怪的短时减速效果。
- PPT 怪需要新的远程接近槽位或偏好距离，不能继续占用贴身攻击圈。

PPT 激光会改变敌人行为和空间压力，必须作为独立阶段验收，不能只替换动画后沿用接触伤害。

## 9. 主角装备与攻击方式

### 9.1 第一批装备

| 装备 | 攻击类型 | 弹药 | 动画 | 定位 |
|---|---|---|---|---|
| 空手 | 前方近战 | 无 | `Punch` | 没有武器时的保底能力 |
| 冲锋枪 | 射线／子弹表现 | 弹匣与后备弹药 | `Shoot`、`Reload` | 当前默认远程武器 |
| 刀 | 前方扇形近战 | 无 | `Slash` | 高风险、稳定近战输出 |

### 9.2 装备数据

建议将当前固定 `DEFAULT_WEAPON` 扩展为配置表：

```ts
type AttackShape = "hitscan" | "meleeArc" | "beam";

type WeaponDefinition = {
  id: "unarmed" | "smg" | "knife";
  displayName: string;
  attackShape: AttackShape;
  damage: number;
  attacksPerSecond: number;
  range: number;
  arcDegrees?: number;
  magazineSize?: number;
  maxReserveAmmo?: number;
  reloadTime?: number;
  animation: "Punch" | "Shoot" | "Slash";
  hitEventTime?: number;
  heldModel?: string;
};
```

升级系统必须明确作用范围：

- 「火力校准」第一版只作用于枪械，避免刀和拳头意外继承散布或弹匣属性。
- 「弹匣管理」只对具有弹匣的武器生效。
- 后续若要强化近战，应新增独立升级路线，而不是复用枪械字段。

### 9.3 拾取与替换

竖屏操作不适合长期占用一个固定拾取键，第一版采用：

- 当前为空手时，进入武器拾取半径自动装备。
- 已有实体武器时，靠近新武器显示短暂“换武器”上下文按钮。
- 替换后旧武器掉在原地，并设置短暂拾取冷却，避免反复自动交换。
- 主角只有一个主武器槽，不引入背包和武器轮盘。
- HUD 显示当前武器图标／名称；近战武器隐藏弹药数字，改显示“近战”。

拾取按钮的位置需要重新进行手机遮挡和误触验收，不能默认塞入已经通过回归的触控区域。

### 9.4 武器挂点

- 在主角骨骼中按名称寻找 Mixamo 右手骨骼，创建统一 `weaponSocket`。
- 武器模型作为独立轻量道具挂载，不为每种武器复制整套人物模型。
- 每种武器保存局部位置、旋转和缩放校准值。
- 如果现有主角网格已经包含不可拆卸武器，需要先确认是否可隐藏或重新导出无武器版本。

## 10. 受击与死亡表现

### 10.1 受击

现有材质闪白继续保留，并与 Hit 动画组合：

| 对象 | 反馈 |
|---|---|
| 主角 | Hit 动画、红色边缘提示、伤害数字、轻微镜头反馈 |
| Bug 怪 | Hit 动画、绿色故障粒子、短闪白 |
| 需求变更怪 | Hit 动画、蓝色便签碎片、短闪白 |
| PPT／会议怪 | Hit 动画、紫色幻灯片碎片、激光笔短暂失效 |

不建议默认使用写实血液。办公室主题粒子更符合当前美术，也能在手机小尺寸下区分怪物类型。如果后续希望增加血液，应作为独立美术方向决定。

### 10.2 死亡

```text
HP <= 0
  ↓
设置 dead，立即停止 AI / 攻击 / 碰撞 / 受击
  ↓
播放 Death，隐藏血条
  ↓
动作后段触发专属碎屑与淡出
  ↓
结算经验和掉落，释放场景对象
```

- 普通怪物死亡表现建议控制在 `0.45～0.8s`。
- 老板可延长到 `1.2～1.8s`，但不能阻塞撤离流程。
- 经验与掉落可以在死亡开始时锁定，在视觉清理时生成，防止重复结算。
- 玩家死亡后立即停止输入和敌人伤害，先播放短 Death，再显示失败面板。

## 11. 角色资产流水线扩展

当前 `$game-character-pipeline` 已稳定支持四视图、Hunyuan 50K、Mixamo 原地 Walk、Blender 转换、1K WebP 和 Meshopt，但尚未建立多 Clip 合并步骤。本设计要求先扩展该流程，再批量生产动作。

### 11.1 基本规则

- 继续使用现有角色网格、贴图和骨骼，不重新生成已经验收的角色。
- 首个自包含模型仍保留 `With Skin`；同一角色的附加 Mixamo 动作应基于同一骨骼，采用经过验证的 `Without Skin` 合并流程。
- Walk、攻击和搜寻动作全部使用 In Place，不把 Root Motion 带入运行时。
- Blender 合并后，一个 GLB 只保留一套网格、材质、贴图和骨骼，并包含多个命名 Animation Clip。
- Clip 名称统一使用 `Idle`、`Walk`、`Shoot`、`Reload`、`Punch`、`Slash`、`Bite`、`Laser`、`Search`、`Hit`、`Death`。
- 继续输出 1K WebP 与 Meshopt；不能为每个动画复制整张贴图。

### 11.2 文件兼容策略

第一阶段继续沿用现有发布文件名 `<slug>_walk_1k_meshopt.glb`，但文件内部可以包含额外 Clip，避免同时修改全部 URL 和缓存路径。等多动画流程稳定后，再单独评估改为更准确的 `<slug>_animated_1k_meshopt.glb`，并同步更新项目 skill 与文档。

### 11.3 资产验收

- GLB 只有一套可用骨骼和预期数量的 Skinned Mesh。
- 所有必需 Clip 名称正确、时长非零且可独立播放。
- 动作不推动角色在世界空间漂移。
- Idle 与 Walk 切换不跳高、不旋转 90°，脚底高度稳定。
- 攻击接触动作与配置的命中事件点一致。
- Death 最后一帧不会恢复站立姿势。
- 多实例能够独立播放不同动作，击中闪白互不影响。
- 贴图为不超过 1024px 的 WebP，Meshopt 模型能在正式加载器中打开。
- 单角色多动画发布包以 `1.5 MiB` 为软目标；超出时先检查重复蒙皮、贴图和无用轨道。

Hunyuan 与 Mixamo 仍是人工检查点。在多 Clip 合并脚本和验证步骤写入项目 skill 前，不批量下载所有角色动作，以免产生不可复用的中间资产。

## 12. 性能与资源预算

- 游戏开始前预加载本局可能出现的全部角色和动画，禁止首次攻击时临时加载。
- 同一角色实例共享几何体和贴图，只克隆骨骼与实例材质。
- 新动画 Clip 不应增加 draw call；若增加，优先检查是否错误复制网格。
- 保持当前最多 13 只敌人的上限。
- 不为枪口、激光和死亡效果恢复数量会变化的动态点光源；继续使用发光 Mesh 和无灯光粒子。
- 正式游玩阶段目标仍为无 50ms 以上工作长帧，动画更新纳入现有 `perf=1` 日志观察。
- 角色总发布包体以约 `6 MiB` 为阶段软目标；老板加入后重新评估。

## 13. 分阶段实施计划

### 阶段 A：动画控制基础

- 新增动画控制器、优先级、播放锁、一次性动作和事件时间点。
- 扩展 `AnimatedCharacter`，支持动作完成、循环控制和回退状态。
- 解决当前 `setMovement()` 每帧覆盖 Attack／Hit／Death 的问题。
- 使用测试 Clip 或现有 Walk 验证控制逻辑，不等待全部美术资产。

验收：优先级、打断、回退和动画事件自动测试通过；现有单 Walk 模型继续兼容。

### 阶段 B：基础动作与战斗反馈

- 为主角和三类怪物制作 Idle、现有攻击、Hit、Death。
- 保持当前冲锋枪和怪物伤害数值不变，只替换表现与命中时序。
- 怪物死亡由立即删除改为死亡阶段清理。
- 增加主题化命中／死亡粒子。

验收：完整 120 秒流程无重复伤害、无尸体攻击、无模型瞬移；手机能辨认四类核心动作。

### 阶段 C：调查／搜寻表现

- 为 `investigate` 增加到点观察阶段。
- 有专属 Search Clip 时播放，没有时使用 Idle 加程序化转向。
- 验证枪声、同伴报警和丢失目标三条路径。

验收：怪物会前往线索、停下观察并回到巡逻；不会恢复旧版状态抖动。

### 阶段 D：怪物差异化攻击

- Bug Bite 与需求怪 Punch 使用近战命中帧。
- PPT 怪改为中距离激光攻击，增加预警、遮挡和远程站位。
- 分别调优攻击距离、前摇、恢复与冷却。

验收：三种怪物不看名称即可从攻击方式区分；激光可躲避且不能穿墙。

### 阶段 E：玩家装备

- 抽象武器配置与当前装备状态。
- 加入空手、刀、地面武器拾取和上下文替换按钮。
- 加入 Punch、Slash、武器挂点和对应 HUD。
- 重新审查现有两个枪械升级对不同装备的适用范围。

验收：三种装备可完整攻击、切换和结算；手机操作不误触，不破坏现有射击与换弹体验。

### 阶段 F：老板

- 按新的多动画标准制作真实老板模型。
- 老板从首次接入即具备 Idle、Walk、Attack、Hit 和 Death。
- 老板专属攻击另行设计，不使用普通怪物动作简单放大。

## 14. 测试方案

### 14.1 自动化测试

- 动画优先级：Death、Hit、Attack、Search、Walk、Idle 顺序正确。
- 一次性动作：完成后回到当前 Locomotion，不重复触发事件。
- 命中时序：跨帧经过事件点只触发一次。
- 死亡安全：Dead 实体不移动、不攻击、不被再次结算经验或掉落。
- 近战判定：角度、距离、障碍和多目标上限正确。
- 激光判定：预警后锁定、墙体截断和主角躲避正确。
- 装备切换：拾取冷却、弹药保存、空手回退和升级适用范围正确。
- 搜寻表现：到点观察、被打断追击和超时返回巡逻正确。

### 14.2 浏览器与手机验收

- 主角静止、移动、连续射击、换弹、受击和死亡逐项检查。
- 三类怪物分别强制生成，检查攻击、受击、死亡和搜寻。
- 多只同类怪同时播放不同动作，确认骨骼实例互不干扰。
- 低帧率模拟下检查攻击事件不漏发、不重复。
- 运行完整成功局与失败局，检查结算优先级未改变。
- 使用 `?perf=1` 检查动画更新、首次动作播放和粒子效果没有新增长帧。
- 覆盖至少两种手机屏幕尺寸，检查拾取提示和按钮不遮挡现有 HUD。

## 15. 完成标准

本设计不能仅以“模型包含动画”视为完成。全部完成需要满足：

- 主角和三类普通怪物具备各自的必需 Clip。
- AI、攻击、动画和伤害时序一致。
- 怪物搜寻有清晰的到点观察表现。
- 受击和死亡不会造成重复结算、尸体攻击或碰撞阻塞。
- 冲锋枪、刀和空手三种攻击形态在手机上可操作。
- PPT 激光具有可识别预警、可躲避窗口和墙体遮挡。
- 自动化测试、生产构建和完整手机回归通过。
- 性能日志未出现由新动画或特效引入的持续长帧。

## 16. 待评审决策

开始阶段 A 前需要确认以下产品方向：

1. 命中特效是否坚持办公室主题碎屑，默认不使用写实血液。
2. 第一版武器范围是否锁定为空手、冲锋枪和刀。
3. 武器替换是否采用“空手自动拾取、已有武器显示上下文按钮”。
4. 主角现有模型中的枪是否可拆分；如果不可拆分，是否制作无武器主角版本。
5. 第一版允许全身攻击动画期间轻微滑步，还是在开始内容制作前先实现上半身动画遮罩。
6. PPT 激光的伤害、射程、前摇和减速时长在实现阶段通过实机调优，不在本稿锁死最终数值。
